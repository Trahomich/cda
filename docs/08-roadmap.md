# Дорожная карта реализации ИС ЦДА: MVP → v1 → v2

Статус: готово · Версия: 1.1 · Дата: 2026-11-05 · Автор: Светлана Куликова

Назначение: разбить реализацию ЦДА на этапы с проверяемыми критериями готовности, оценить
трудоёмкость блоков, зафиксировать риски (RISK-NN, определены только здесь), метрики успеха MVP
и вопросы, которые нужно решить до старта реализации. Вход: docs/01-requirements.md (MoSCoW),
docs/02-architecture.md (модули, ADR-01…05), docs/06-data-api.md (DAT, API), docs/07-ux.md
(экраны E-NN), docs/09-ai.md (ИИ-блок), выводы docs/research/*.md (оба исследования завершены:
REC-01…15 — аналоги, REC-16…25 — источники данных). PWA-клиент в составе MVP — ADR-03;
детализация в docs/10-mobile-pwa.md. Пост-MVP блоки этапа v2 — docs/11-agroscouting.md
(агроскаутинг) и docs/12-economics.md (экономика), включены в §3 (версия 1.1).

Принцип деления: MVP — минимальный замкнутый контур ценности агронома «поля → план → работа →
факт → данные/алерты» с мобильным полевым клиентом; v1 — рекомендации, животноводство и ИИ-блок;
v2 — экономика и расширенные интеграции. Этапы не равны приоритетам MoSCoW дословно: часть
M-требований (животноводство) осознанно отнесена к v1 — вне контура агронома MVP.

## 1. Этап MVP — замкнутый контур агронома с PWA

Состав по REQ-F (M-приоритет): поля и севооборот [REQ-F-001..003, 005..007], справочник и планы
удобрений/СЗР с контролем сроков ожидания [REQ-F-009, 010, 012, 013], базовая техника и задания
[REQ-F-014, 015], погода и погодные окна [REQ-F-023..025], спутниковый NDVI [REQ-F-027, 028],
журнал адаптеров [REQ-F-034]. Нефункциональные: [REQ-NF-001..003, 005, 006, 008, 009].

- Модули (02 §4): mod-fields, mod-rotation, mod-inputs (без баланса доз), mod-weather,
  mod-satellite, mod-machinery (парк и задания), ingest-gateway (IF-WEATHER, IF-SATELLITE,
  импорт файлов полей/агрохимии IF-SOIL в объёме загрузки), API-модуль, PWA-клиент.
- DAT/API (06): API-01..18, 27..29, 32 (+30 частично, импорт агрохимии — v1 с REQ-F-031);
  DAT ядра §2, включая dat_source_journal — журнал состояний адаптеров (05 §6, REQ-F-034,
  экран E-14); ref_culture, ref_predecessor_matrix, ref_agrochem, ref_source, ref_weather_rule.
- Экраны (07): E-01..E-11, E-13, E-14, E-15 (агрономические справочники), E-16, E-17, E-18.
- PWA: офлайн-очередь E-17, полевой журнал E-08 (ADR-03; docs/10-mobile-pwa.md).
- Критерий готовности (проверяемый): сквозные сценарии SC-01, SC-03, SC-04 пройдены на пилотном
  хозяйстве на данных реального сезона ≥1 месяц; метрики §4 достигнуты; все API этапа отвечают
  ≤2 с (p95) [REQ-NF-002]; экспорт данных хозяйства работает [REQ-NF-007 — базово JSON/CSV].

Трудоёмкость блоков MVP: поля+контур+версии — L; севооборот с проверками RULE-AGRO-01..04 — M;
справочник+планы СЗР/удобрений (без расчёта доз) — M; журнал работ + PWA офлайн — XL; погода
(адаптер+окна) — M; спутник (Sentinel-2 конвейер, NDVI) — L; API-модуль и права/аудит — L;
адаптеры/журнал источников — M. Суммарно MVP ≈ 4×L + 4×M + XL (ядро системы).

## 2. Этап v1 — рекомендации, животноводство, ИИ

Состав по REQ-F: расчёт доз N-P-K и NDVI-поправки [REQ-F-011, 030, 031; RULE-AGRO-05..07],
агрохимия в карточке [REQ-F-004], пары/сидераты [REQ-F-008], телематика: импорт треков и
фактическая площадь [REQ-F-016, 032], ТО [REQ-F-017], аномалии NDVI [REQ-F-029], алерты опасных
явлений [REQ-F-026], животноводство [REQ-F-018..021] с кормовой связью в севооборот (SC-05).
ИИ-блок (docs/09-ai.md §7): AI-объяснения и сводки [REQ-F-037, 038, API-34, API-35] — Could,
но включены в v1 как главный дифференциатор «двойника» (REC-11); чат [REQ-F-035, 036, API-33]
— только при GPU-режиме (§6, вопрос Q1). Нефункциональные: [REQ-NF-004, 007, 010].

- Модули: mod-livestock, rules-engine (полный RULE-AGRO + RULE-TECH/LIVE), ИИ-блок за API
  (ADR-05, ADR-02 архитектуры 02), VRT-экспорт карт (E-09).
- DAT/API: API-19..26, 30, 31, 33..35; dat_ration/dat_vet_event/dat_manure_yield и пр. (04).
- Экраны: E-12 (животноводство), расширение E-05/E-09/E-13 объяснениями ИИ.
- Критерий готовности: SC-02 и SC-05 пройдены полностью; доза N-P-K выдаётся с обоснованием,
  принимающимся агрономом (метрика §4); ИИ-объяснения человекопроверяемы (эталонный набор
  вопросов 09-ai §7); карантин блокирует перемещения [RULE-LIVE-01].

Трудоёмкость: правила доз — M; телематика-импорт — L; животноводство — XL; ИИ-блок — L
(+ отдельное решение по железу); ТО и алерты — S; аномалии NDVI — M.

## 3. Этап v2 — экономика, агроскаутинг и расширенные интеграции

Состав: экономика производственной модели [REQ-F-033, REQ-F-039..042 — 01 §3.10; сценарии
EC-01..06, API-40..45 — docs/12-economics.md], агроскаутинг [AS-01..05, API-36..39 —
docs/11-agroscouting.md; по решению пользователя выведен из MVP], навоз в балансе
[REQ-F-022], интеграции прямых API телематики-интеграторов (REC-20), коммерческая
досъёмка (REC-24), Ветис/Меркурий, Landsat как резерв (REC-21), прочие расширения по спросу.

Экономика — этапность внутри v2 (12 §7): шаг 1 — цены и калькуляция культурного цикла
[EC-01..03, расширение REQ-F-033]; шаг 2 — экономика животноводства [EC-04, после контура
v1: dat_ration, dat_production_record]; шаг 3 — переработка [EC-05] и P&L [EC-06] — только
при наличии переработки в хозяйстве (вопрос пользователю, аналог Q6 §6). Критерий
готовности (12 §8): калькуляция цикла сходится с контрольным расчётом экономиста ±2 %;
себестоимость молока руб/л — ручная проверка ±5 %; у каждой позиции отчёта data_ref на
исходную запись или пометка manual; отсутствие цены не ломает отчёт (позиция в натуральных
единицах).

Агроскаутинг — фотофиксация проблем полей из PWA (полевой режим), локальное CV-распознавание
(расширение ai-assistant, ADR-05) с человеком-в-контуре: план СЗР порождается только после
подтверждения диагноза (confirmed_by). Критерий готовности (11 §6): сценарии AS-01..05
проходят на демо-хозяйстве; точность топ-1 кандидата CV ≥ 70 % на выборке ≥ 100 фото культур
MVP; офлайн-сценарий «20 фото без сети → синхронизация»; автотест «нет плана без
confirmed_by».

Критерий готовности интеграций: контрактные интеграции опробованы на ≥2 хозяйствах.
Трудоёмкость: цены+калькуляция цикла — M; экономика животноводства — M; переработка и
P&L — L; агроскаутинг (CV-модуль, дообучение, расширение PWA) — L; прямые API телематики —
L; Ветис — XL (бюрократия); коммерческие снимки — M.

## 4. Метрики успеха MVP

| Метрика | Целевое значение к концу первого сезона на пилоте |
|---|---|
| Поля с контурами и текущей культурой | ≥ 90 % площадей хозяйства |
| Операции, внесённые через систему (план + факт) | ≥ 70 % полевых операций журнала |
| Использование погодного окна при планировании СЗР | ≥ 50 % обработок планируется с окном [REQ-F-025] |
| Просмотр NDVI-таймлайна агрономами | ≥ 1 раз/неделю в сезон на активного пользователя |
| Рекомендации с открытым «Почему?» | ≥ 40 % показанных (REQ-NF-006) |
| Офлайн-записи без конфликтов после синхронизации | ≥ 95 % (REQ-NF-003) |
| Время ответа API | ≤ 2 с, p95 (REQ-NF-002) |

## 6. Вопросы пользователю до старта реализации

1. **Режим ИИ-железа** (09-ai §5): минимальный CPU (32 ГБ RAM) или GPU 24 ГБ для чата —
   определяет состав AI в v1 (только объяснения/сводки или + чат).
2. **Пилотное хозяйство и регион**: культуры и набор справочников MVP (8–12 культур средней
   полосы или иной список), источник агрохимии, формат картограмм подрядчика.
3. **Телематика**: какой интегратор установлен (Wialon/Omnicomm/иное) — определяет приоритет
   прямого API в v2 (REC-20) и формат импорта MVP.
4. **Развёртывание**: облако или контур хозяйства (влияет на ИИ и REQ-NF-005), резервное
   копирование и железо сервера (REQ-NF-010).
5. **Животноводческий контур в v1**: какие группы/продуктивность вести в первую очередь,
   есть ли действующая ИС для импорта (SC-05, 04 §животноводство).
6. **Приоритет v2-экономики**: доступность данных о ценах закупки/реализации хозяйства.

## 7. Учёт выводов исследований

Оба исследования завершены и использованы: состав источников MVP — REC-16, 17, 18, 19, 20
(погода Open-Meteo, Sentinel-2, импорт агрохимии, внутренние справочники, CSV/ISOXML-импорт
телематики); функциональные ориентиры — REC-01..05 (карточка поля, NDVI-алерты, VRT),
REC-09..11 (животноводческо-полевой контур, нормативы РФ, объяснимость). Пробел, помеченный в
research/01 §5: отдельное мини-исследование животноводческих ИС для v1 (4–6 недель до старта
этапа) — не блокирует MVP и v1-агрономию.
