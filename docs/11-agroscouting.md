# Агроскаутинг: фотофиксация и распознавание проблем полей (пост-MVP)

Статус: черновик · Версия: 1.0 · Дата: 2026-11-05 · Автор: Иван Куликов

Решение пользователя: агроскаутинг **не входит в MVP** (08-roadmap, состав MVP).
Документ фиксирует проектное решение, чтобы после MVP расширение не потребовало
переработки ядра. Опирается на docs/02-architecture.md (ADR-04, ADR-05),
docs/03-domain-agronomy.md (ENT-ALERT, ENT-RECOMMENDATION, ENT-CROP-CYCLE),
docs/05-integrations.md (§5 trust), docs/06-data-api.md (DAT, API),
docs/09-ai.md (локальный инференс, guardrails), docs/10-mobile-pwa.md (полевой режим).

## 1. Назначение и границы

Агроскаутинг — полевой осмотр полей с фотофиксацией: агроном (или скаут) обходит
поле, фотографирует растения и проблемные участки, система распознаёт болезни,
вредителей, сорняки и абиотические повреждения, привязывает наблюдение к полю,
культурному циклу и точке на карте. Результат — алерты и входные данные для
планов СЗР (ENT-TREATMENT-PLAN), а не автоматическое применение препаратов.

За границами блока: замена лабораторных анализов, диагностика болезней животных,
обработка фото от дронов (отдельное расширение v2+, см. §7).

## 2. Сценарии (AS-NN)

| ID | Сценарий | Успех |
|---|---|---|
| AS-01 | Обход поля с фотофиксацией: скаут открывает поле на карте (E-03), ведёт визит, снимки делаются из PWA с геометкой | визит сохранён, каждое фото привязано к точке (GeoJSON §5 CONTRACTS) |
| AS-02 | Распознавание проблемы по фото: локальная CV-модель возвращает кандидатов-диагнозов с confidence | топ-3 кандидата показаны, человек выбирает или вводит свой |
| AS-03 | Создание алерта по наблюдению: подтверждённый диагноз порождает ENT-ALERT с data_refs на наблюдение | алерт виден руководителю и в журнале E-13 |
| AS-04 | Вход в план СЗР: наблюдение (болезнь/вредитель) предлагается как основание плана обработки | черновик ENT-TREATMENT-PLAN со ссылкой на наблюдения |
| AS-05 | Карта проблем поля: сгущение наблюдений за цикл по проблемам на фоне NDVI (ENT-SATELLITE-SCENE) | тепловая карта на E-03, фильтр по проблеме и дате |

## 3. Сущности и данные

### ENT-SCOUT-VISIT — визит осмотра поля

| Поле | Тип | Комментарий |
|---|---|---|
| id* | uuid | PK |
| field_id* | uuid | FK dat_field |
| cycle_id | uuid | FK dat_crop_cycle, null вне сезона |
| started_at* / finished_at | datetime | ISO 8601, UTC |
| inspector_id* | uuid | пользователь |
| track | geometry(LineString, WGS84) | пройденный маршрут, null если GPS не вели |

### ENT-SCOUT-OBSERVATION — наблюдение (проблема на точке)

| Поле | Тип | Комментарий |
|---|---|---|
| id* | uuid | PK |
| visit_id* | uuid | FK ENT-SCOUT-VISIT |
| location* | geometry(Point, WGS84) | из EXIF или GPS-сессии |
| photo_ref* | str | ссылка на объектное хранилище (как track_ref в 06) |
| problem_class* | enum | disease, pest, weed, abiotic, other |
| diagnosis_id | uuid | FK ref_problem (новый справочник) |
| confidence | decimal(4,3) | вывод CV-модели, null при ручном вводе |
| cv_candidates | jsonb | [{diagnosis_id, confidence}, ...] — до 3, по §5 CONTRACTS |
| confirmed_by | uuid | кто подтвердил диагноз; null — непроверено |
| severity | enum | low, medium, high, null |

Новые таблицы (дополняют 06-data-api.md §2): dat_scout_visit — UQ(field_id,
started_at, inspector_id); dat_scout_observation — IX(problem_class, confirmed_by),
GIST(location). Новый справочник ref_problem (id, name, problem_class, культура,
текст описания, типовые меры) — предзаполнен по культурам MVP.

## 4. Поток данных и распознавание

1. Фото с геометкой загружается из PWA (полевой режим, 10-mobile-pwa §3):
   офлайн-очередь, затем POST по новому API (§5).
2. Сервер: проверка попадания точки в контур поля (PostGIS), извлечение EXIF,
   фото — в объектное хранилище, запись dat_scout_observation со статусом
   `cv_pending`.
3. CV-модуль (расширение ai-assistant, ADR-05): инференс локальной открытой
   CV-модели (детекция + классификация листьев; выбор весов — до старта этапа,
   кандидаты: модели на COCO/PlantVillage-подобных датасетах, дообучение на
   снимках культур хозяйства) ИЛИ внешней CV-API (решение пользователя: распознавание
   болезней/вредителей возможно по внешним моделям). При внешней модели отправляется
   только само фото — без привязок к полю, хозяйству и координат; выбор фиксируется
   в ADR при старте этапа. Результат — cv_candidates + confidence.
4. Человек-в-контуре: диагноз считается подтверждённым только после выбора
   скаутом/агрономом (AS-02); без подтверждения наблюдение не порождает планов.
   Guardrail как в 09-ai §3: система не создаёт рекомендации без данных-ссылок.
5. Подтверждённое наблюдение → ENT-ALERT (AS-03) → основание плана СЗР (AS-04).

## 5. API (дополняют 06-data-api.md §5, пост-MVP)

| ID | Метод и путь | Назначение | Трассировка |
|---|---|---|---|
| API-36 | POST /scout/visits | создать визит (обязательные точки маршрута) | AS-01 |
| API-37 | POST /scout/observations | загрузить фото+точку (multipart; EXIF обязателен при location) | AS-01, AS-02 |
| API-38 | GET /scout/observations?field_id&problem_class&date_from | список/карта наблюдений | AS-05 |
| API-39 | POST /scout/observations/{id}/confirm | подтверждение диагноза человеком | AS-02, AS-03 |

Ошибки — RFC 7807 по §8 CONTRACTS: 422 `point_outside_field`, 415 — не изображение,
413 — фото > 15 МБ (лимиты §5 CONTRACTS).

## 6. Приёмка этапа (проверяемо, пост-MVP)

1. Сценарии AS-01..AS-05 проходят на демонстрационном хозяйстве.
2. Точность топ-1 кандидата CV ≥ 70 % на выборке ≥ 100 фото культур MVP
   (замер на отложенной выборке, отчёт в dat_audit).
3. Каждое наблюдение с планом СЗР имеет data_refs на observation_id
   (проверка запросом).
4. Офлайн-сценарий: 20 фото в поле без сети → синхронизация → все наблюдения
   на карте с точками.
5. Ни одно наблюдение не порождает план без confirmed_by (автотест).

## 7. Открытые вопросы

- Датасет болезней/вредителей для культур РФ: собрать силами хозяйства на пилоте
  или лицензировать; объём для дообучения (оценка: 300–500 фото на класс).
- Точность GPS телефона на краю поля (±5–15 м): предлагать привязку к полю
  вручную, если точка вне контура (список ближайших полей).
- Дроны/фотоплощадки: отдельное расширение v2+ (очередь батч-обработки);
  в этой версии — только фото с телефона.
