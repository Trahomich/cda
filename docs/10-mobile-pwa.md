# Мобильное PWA-приложение ЦДА (состав MVP)

Статус: готово · Версия: 1.0 · Дата: 2026-11-05 · Автор: Иван Куликов

Опирается на docs/01-requirements.md (REQ-NF-003, SC-03, SC-04), docs/02-architecture.md
(ADR-03: PWA вместо нативных приложений), docs/07-ux.md (экраны E-NN, wireframes,
принципы §1) и docs/06-data-api.md (API-17, API-20, API-27). Требование пользователя:
в MVP мобильный клиент реализуется как PWA.

## 1. Область и роли

PWA — тот же веб-фронтенд ЦДА (SPA, ADR-03), установленный на домашний экран;
«полевой режим» — ограниченный набор экранов и офлайн-возможности. Полные
«кабинетные» экраны доступны в браузере на десктопе без установки PWA.

| Роль | Полный PWA | Полевой режим (офлайн-приоритет) |
|---|---|---|
| Механизатор | E-08, E-11 (свои машины), E-13, E-17 | задания смены, ввод выполненных работ, офлайн-очередь |
| Агроном | все экраны, кроме E-14..E-16 | E-03, E-06, E-08, E-10, E-13 + офлайн-очередь |
| Руководитель/Зоотехник/Администратор | браузер; PWA — по желанию (просмотр) | — |

Экраны MVP в PWA (по 08-roadmap составу MVP): E-01, E-02, E-03, E-06, E-07, E-08,
E-10, E-13, E-17. Экраны E-04, E-05, E-09 — адаптированы к мобильному, но полная
версия — десктопная.

## 2. Технологии

| Компонент | Выбор | Обоснование |
|---|---|---|
| Основа | SPA-фреймворк (фиксация при старте реализации, ADR-02 02-architecture §7) | один код для веба и PWA |
| Установка | Web App Manifest (name, icons 192/512, display: standalone, theme) | установка «На экран «Домой»» iOS/Android |
| Кэш ассетов | Service Worker (precache shell + stale-while-revalidate ассетов) | мгновенный старт офлайн |
| Данные офлайн | IndexedDB (таблицы: задания, справочники, очередь операций, кэш карточек полей) | надёжное локальное хранилище >5 МБ |
| Синхронизация | Background Sync API (Android/Chrome) + ручная кнопка «Синхронизировать» (все платформы) | iOS не поддерживает Background Sync — ручной режим обязателен |
| Пуш-уведомления | Web Push (VAPID) | iOS — с 16.4 и только для установленной PWA; деградация — бейдж при открытии |
| Карты офлайн | кэш тайлов полей хозяйства на 2 уровня зума + растровые «снимки» контуров | карты — ядро полевого UX, но не бесконечный кэш |

## 3. Модель офлайн-работы (REQ-NF-003)

1. Перед выездом (онлайн) PWA синхронизирует: задания на смену, карточки назначенных
   полей (контур, план, ограничения СЗР — RULE-AGRO-08/09), справочники (машины,
   препараты), погоду на 3 суток.
2. В поле (офлайн): механизатор выполняет задания, вводит факт операции (E-08) —
   запись кладётся в очередь E-17 (IndexedDB) со статусом `pending`.
3. При появлении сети: очередь отправляется по API-17 (POST /operations) по одной
   записи; конфликт версий (например, изменившийся план) — по правилу «факт важнее
   плана»: факт сохраняется, расхождение >10 % помечается deviation_flag (03 §1.6).
4. Приёмка офлайн: сценарий — самолётный режим, ввод 3 операций, выход из режима,
   синхронизация — все 3 записи появляются в журнале с датами и исполнителем.

Очередь хранит: entity (operation/machine_job), payload (по формату API), created_at
локально, retry_count. Неудачная отправка (422) не удаляет запись: показывается
причина из problem+json, запись можно исправить или удалить вручную.

## 4. Ограничения платформ (зафиксировать в тестах)

- iOS Safari: нет Background Sync → синхронизация только при открытом приложении;
  хранилище IndexedDB может вытесняться при нехватке места (7 дней без открытия —
  предупреждение в UI после 3 дней неактивности); push — только установленной PWA.
- Android/Chrome: полная поддержка Background Sync и push.
- Геолокация в поле: GPS работает офлайн; координата не заменяет выбор поля
  (контур определяет система), но предлагается как подсказка.

## 5. Обновления и версия

- Service Worker обновляется по стратегии «activate on next launch»: при выходе новой
  версии пользователь видит баннер «Доступна новая версия — применится при перезапуске».
- Совместимость кэша и API: поле `api_version` в ответах (мажор /api/v1); при смене
  мажора старая очередь всё равно отправляется (обратная совместимость формата операций).

## 6. Приёмка MVP-состава PWA (проверяемо)

1. Установка на iOS и Android: иконка, standalone-запуск, сплэш — по манифесту.
2. Офлайн-сценарий §3.4 проходит на обеих платформах.
3. Пуш об алерте погоды (REQ-F-026) доходит на Android; на iOS — при открытой PWA
   или в виде бейджа (деградация задокументирована).
4. Lighthouse PWA-аудит: installable = yes, офлайн-старт ≤3 с на средний телефон.
5. Экраны §1 соответствуют wireframes 07-ux (E-08, E-17 — дословно).

## 7. Открытые вопросы

- Push-сервер (Web Push + VAPID) — добавить в стек при старте реализации MVP.
- Кэш тайлов: провайдер карты (OSM self-hosted или коммерческий) — выбрать до старта
  MVP по лицензии для офлайн-тайлов.
- iOS-ограничение 7 дней: рассматривать нативную обёртку (Capacitor) только если
  полевые пользователи подтвердят проблему на пилоте (v1).
